## Что это за проект

Telegram-бот на базе LLM-агента для маркетолога, ведущего ~10 рекламных
проектов. Агент понимает вопросы на естественном языке, сам выбирает
инструменты (tool use), тянет данные и формулирует выводы.

Две роли в одном агенте:
- **Аналитик кампаний** — метрики, динамика период-к-периоду, аномалии.
- **Специалист по Яндекс.Директу** — семантика, минус-слова, объявления.

## Архитектура и поток данных

```
Telegram (bot.py)
   → agent.py  (цикл tool-use: LLM решает, что вызвать)
       → tools.py  (инструменты: схемы для модели + Python-функции)
           → data.py  (источник данных: сейчас мок, потом Яндекс.Директ)
```

| Файл | Назначение |
|------|-----------|
| `bot.py` | Telegram-интерфейс (aiogram 3.x), память диалога по chat_id |
| `agent.py` | Цикл tool-use на Anthropic SDK + системный промпт |
| `tools.py` | Инструменты: `DISPATCH` (имя→функция) и `TOOL_SCHEMAS` (JSON-схемы) |
| `data.py` | `MockProvider`, заглушка `YandexDirectClient`, агрегации, детектор аномалий |
| `config.py` | Настройки из `.env` |

## Ключевые конвенции — соблюдай

1. **Не ломай мок-фолбэк.** Бот должен запускаться и работать без реальных
   доступов к API. `data.get_provider()` — единственная точка переключения
   источника данных. Любая реальная интеграция должна оставлять возможность
   вернуться на `MockProvider`.
2. **`data.py` и `tools.py` — без тяжёлых зависимостей.** Только стандартная
   библиотека (плюс `requests` для реального клиента Директа). Это позволяет
   быстро прогонять их в тестах без установки `aiogram`/`anthropic`. Если
   нужен `pandas` — обоснуй и вынеси в отдельный модуль.
3. **Добавление инструмента = три места:** функция, запись в `DISPATCH`,
   объект в `TOOL_SCHEMAS`. Имена должны совпадать.
4. **Контракт цикла tool-use в `agent.py` не меняй без причины.** Он опирается
   на `resp.stop_reason == "tool_use"` и блоки `tool_use` / `tool_result`.
5. **Язык:** комментарии, строки бота и системный промпт — на русском. Суммы — рубли.
6. **Секреты только из `.env`.** Никаких токенов в коде или коммитах.
   `.env` должен быть в `.gitignore`.
7. **aiogram 3.x** (Router/Dispatcher), не 2.x. Модель LLM — из `config.MODEL`
   (по умолчанию `claude-sonnet-4-6`), не хардкодь.

## Как запустить и проверить

```bash
pip install -r requirements.txt
cp .env.example .env          # заполнить TELEGRAM_TOKEN и ANTHROPIC_API_KEY
python bot.py
```

Смоук-проверка инструментов без LLM и без сети (прогоняй после правок в
`data.py`/`tools.py`):

```bash
python smoke_test.py
```

Если `smoke_test.py` ещё нет — создай его по образцу: импортирует `tools`,
вызывает `list_projects`, `get_metrics`, `compare_periods`, `find_anomalies`,
`expand_keywords`, `validate_ad` и печатает результаты. Он не должен требовать
сетевых вызовов.

## Рабочий процесс

- Бери задачи из `SPEC.md` по порядку приоритета.
- Одна задача = один логический коммит/PR. Не смешивай задачи.
- После изменений в данных/инструментах прогоняй `smoke_test.py`.
- Если задача блокирована (например, нет токена Директа) — переходи к
  следующей незаблокированной и отметь это.
